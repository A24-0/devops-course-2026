1. Почему в Git ветвление «дешёвое», а в **SVN** — «дорогое»? В Git ветка — это всего лишь текстовый файл с указателем на хеш коммита, её создание не копирует данные и занимает миллисекунды. В **SVN** ветка реализована как копия директории в репозитории на центральном сервере, поэтому операция требует обращения к серверу и работы с деревом каталогов.
2. Можно ли в **SVN** сделать коммит без интернета? Нет. **SVN** — централизованная система: единственная полная копия истории хранится на сервере, и коммит означает запись в эту копию. Без связи с сервером доступны только локальные правки файлов. В Git история хранится у каждого разработчика целиком, поэтому коммиты, ветвление и просмотр истории работают офлайн.
3. В каких сценариях **SVN** может быть предпочтительнее? При поддержке legacy-проектов, уже построенных вокруг **SVN** (госсектор, банки); при работе с очень большими бинарными файлами, когда не нужна полная локальная копия истории; при необходимости жёсткого централизованного разграничения прав доступа на уровне отдельных каталогов, что в Git реализуется сложнее.
